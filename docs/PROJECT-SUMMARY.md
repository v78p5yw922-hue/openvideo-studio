# 第一部分：技术细节

## 1. 一句话

**把中文短剧剧本，编译成 MiniMax H3 能吃的中英混合提示词，跑通「校验 → 渲染 → 审核 → 选版 → 合成」的完整流水线，全部操作在 Web UI 里。**

## 2. 系统结构

```
┌──────────────────────────── Windows（D:\AI\DeepSeekProjects\OpenVideo）───────────────┐
│  源码 + 项目数据（剧本/分镜/参考图/成片）+ 部署脚本 + 文档                              │
│                                                                                        │
│  studio/web-src  ──(vite build)──►  studio/web/dist  ──┐                               │
│  studio/core, studio/api, studio/exec（FastAPI）        │                               │
└────────────────────────────────────────────────────────│───────────────────────────────┘
                                                          │ deploy-to-wsl.ps1（同步 + 重启）
┌──────────────────────────── WSL2 Ubuntu 22.04 ──────────▼───────────────────────────────┐
│  /home/agent/openvideo/video-agent      ← 部署副本（studio + scripts，跑服务）           │
│  /home/agent/openvideo/studio-data       ← 运行时数据（SQLite + 参考图 + takes + 成片）   │
│  studio.service  :8801  FastAPI + 内置执行器（runner.py 线程）                            │
│  comfyui-h3-045.service :8288  ComfyUI 0.45.3 + comfy-kitchen 0.2.41（自定义节点包）      │
│  RTX 4090 24 GB（WSL 直通），权重见 §5                                                    │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

**关键点**：D 盘是**源码与数据**，WSL 是**运行环境**。UI 在 Windows 浏览器访问 `http://127.0.0.1:8801`。

## 2.1 目录归属（代码 / 数据 / 内容 三分）

```
<仓库>/                      代码：studio、scripts、web-src、docs、examples
<仓库>/content/<剧名>/       创作内容：剧本、分镜、场景清单、内容简报   ← 不进版本库
<数据目录>/                  运行时数据：SQLite、takes、参考图、成片      ← 不进版本库
  ~/.local/share/openvideo/studio-data  (或环境变量 STUDIO_DATA)
config.toml                  实例配置：引擎地址、模型名、数据/内容目录、渲染默认值
```

**原则**：代码可以放慢盘（读一次），数据必须放本机快盘；内容可以随便放（会被导入 DB）。
路径全部可配：`config.toml` 或同名环境变量（`STUDIO_DATA`、`OPEN_VIDEO_COMFYUI`、
`OPEN_VIDEO_CONTENT_DIR`），优先级 项目设置 > 环境变量 > config.toml > 内置默认。

## 4. 数据模型（SQLite，16 张表）

```
project_groups → projects → scenes / shots / takes / reviews / previews / jobs / events
characters（跨项目共享）→ asset_versions（参考图历史）
project_cast（本剧覆盖：描述/参考图）
asset_groups / asset_candidates（资产工坊，在建）
users / sessions（登录，Trae 新增）
```

核心不变量是 **指纹（fingerprint）**：

```python
fingerprint = sha256(镜头字段 + 场景卡 + 角色参考图 sha + 编译后的 prompt + 时长 + 转场)
```

镜头状态由「指纹比对」推导：`clean`（有片段且指纹一致）/ `stale`（改过稿）/ `missing`（没渲过）。
这是整个「改稿后知道哪些镜要重渲」「混版合成不静默」的基础。

## 5. 模型与节点（外部依赖，WSL 内）

| 类型 | 文件 | 大小 | 用途 |
|---|---|---|---|
| 视频 UNET（首末帧） | `minimax_h3_fl2va_pruned_int8_convrot` | 19.5 GB | i2v / 锚定母版 |
| 视频 UNET（参考图） | `minimax_h3_ref2va_pruned_int8_convrot` | 19.5 GB | 角色一致性 |
| 图像 UNET | `minimax_h3_image_pruned_int8_convrot` | 19.5 GB | 文生图 / 关键帧 |
| 文本编码器 | `qwen3vl_32b_minimax_h3_int8_convrot` | 25.3 GB | 三种模型共用 |
| VAE | `video_vae_fp16` / `audio_vae_fp32` / `image_vae_fp16` | 1–2 GB | 解码 |

**节点（真正的耦合点）**：

```
ComfyUI 0.45.3（必须 ≥0.45，因为 MiniMaxH3AddGuide 是 0.45.3 才有）
comfy-kitchen 0.2.41 → H3CastMember / H3CastToVideo（把角色卡编译成 H3 的参考通路）
原生 MiniMaxH3* 节点、MiniMaxH3AddGuide（帧钉）
```

## 6. 生成约束（实测数字，写进代码的常量）

| 项 | 值 | 说明 |
|---|---|---|
| 分辨率 | **1344×768 横屏**（固定） | H3 原生档位；竖屏未启用 |
| 时长 | **5 / 8 / 10 秒**（15 秒已弃用） | 帧数 124 / 192 / 243，满足 `17k+5` |
| 步数 | 20 | 少步会糊，多步无收益 |
| cfg | 1（**无负面提示词分支**） | H3 没有 negative |
| 显存峰值 | 16–23.5 GB / 24 GB | 三条分支都要分片 staged 加载 |
| 单镜耗时 | 5s≈9min · 8s≈17min · 10s≈27min（75–79 s/步） | 15s≈50min（152 s/步，弃用） |
| 参考槽 | 9 张（人物 + 场景共享） | 3 角色 = 9 槽，就没场景位 |
| 帧钉 | 0.45.3 的 AddGuide，钉 `frame_idx` | 负数为从片尾倒数 |

**硬限制（踩过的坑）**：

```
· 人物镜走 cast 分支（ref2va）：能挂 9 张参考，但没有首帧输入
· 首末帧走 i2v 分支：能钉首帧，但人物会变脸
· AddGuide 是唯一能两者兼得的路（不占参考槽）
· 模型不跨镜继承状态：肉是生是熟、门开没开、鞋在不在脚上，每镜都要重写
```

## 7. 渲染链路（一次「生成」发生了什么）

```
1) UI 选镜 → POST /api/projects/{pid}/shots 提交 plan
2) 执行器 runner.py：按镜顺序出队（全局单队列，串行）
3) render_adapter.write_script()：从 DB 生成 render.json（编译后的中英混合 prompt）
4) 子进程 render_drama.py --only sNN：
     · 组 ComfyUI 工作流（cast 节点 或 i2v + AddGuide + 场景母版）
     · POST /prompt，轮询 /history，读进度
5) 产物落 takes/sNN_vN.mp4 + 抽 lastframe（供下一镜帧钉）
6) record_take()：写 fingerprint / metrics(ssim/亮度/响度) / dialogue（字幕唯一来源）
7) 审核：pass / reject（带原因）→ 版本可选「选用」
8) 合成：merge.py 拼接（重采样 + 音频对齐）→ finalize.py 烧字幕 + 导出 SRT
```

## 8. 剧本契约（人写的一层）

**镜头表 10 列**：镜号 / 场景 / 出场角色 / 机位 / 动作 / 台词 / 音效 / 配乐 / 转场 / 锚定

**每镜 prompt**（七槽 + 三个新槽）：

```
【机位】景别 / 高度 / 角度 / 运镜 / 距离   （枚举值，写错即报错）
【接续】无 / 接上一帧 / 姿势承接 / 动作中段   ← 按镜决定，支持混用
【服装状态】单镜穿着（整集造型写角色卡/本剧覆盖）
【人物】- 角色：位置/层级/朝向/视线/占比
【关系】面对面/并肩/一前一后/蹲在脚边…（人+动物必须写）
【语气】压低/急促/发颤/咬牙/轻描淡写/柔和/平静…（枚举 11 个）
【开口】秒数
【节奏】0.0 … | 1.2 … | 2.8 …       ← 只写看得见的动作，声音进【音效】
【场景】房间锚点 + 固定物件 + 前景虚化 + 光源
【画质】统一风格串
```

**规则**：`RULES-STRICT.md` 60 条（台词人话、节拍密度、状态/前置/去向、门的歧义、步态锁…）

**校验器**：`validate.py` **54 个校验码**，分八类（契约/机位/人物/台词/节拍/道具/接续/一致性），
分「阻断（渲出来一定废）／建议（能渲但会难看）」。

**词库**：`studio/data/script-glossary.json`（7 类 150+ 条中文词：手部动作/身体位移/道具状态/视线/光/接续/声音），
校验器从这份 JSON 读表 —— 换剧情只改数据，不改代码。

## 9. 已实现的功能（按用户旅程）

```
① 剧本：Markdown 导入 → 解析成项目/场景/角色/镜头（原子性刷新，保留 takes）
② 契约校验：54 码 + 逐条改法；UI 里点错误直接跳到那一镜
③ 素材：角色卡（多参考图 + 一致性锁 + 服装锁/步态锁）、场景卡（母版 + 附加机位图）、本剧覆盖
④ 生成：选镜 → 计划预览 → 入队 → 进度（阶段+百分比+日志）→ 取消
⑤ 版本管理：每镜多 take、指纹标记 stale、选用/采纳/批量选最新
⑥ 审核：pass / reject + 原因；reject 进入待改队列
⑦ 音频：BGM/环境声铺床（sidechain ducking），报告「没铺的原因」
⑧ 合成：拼接、重采样、烧字幕、导出 SRT、EDL/Markdown 导出
⑨ 运维：模型状态、GPU/队列状态、日志 tail、登录与会话（新加）
⑩ 资产工坊（在建）：文生图/图生图、分辨率预设、提示词词库、候选入库
```

## 10. 工程亮点（面试可讲）

1. **契约先行**：54 个校验码把「提示词写作」变成可测的静态分析，返工从「渲完才知」变成「渲前拦截」。
2. **指纹 + take 版本**：改稿只重渲受影响的镜；混版合成时按 take 的记录说话（字幕来源 = 该 take 的台词）。

4. **可观测**：任务阶段、GPU、模型加载、尾日志；失败有明确原因（超时/显存/引擎无响应）。
5. **双层审稿**：本地校验器（机械规则）+ LLM 审稿 skill（剧本层，A 写 B 审），实测第 1 集拦下 5 条废片级问题。

# 第二部分：产品与开源评估

## 11. 它是不是一个独立产品？

**是「带明确边界的应用」，不是「从零自研的模型产品」。** 分三层看：

| 层 | 内容 | 独立度 |
|---|---|---|
| **业务层**（我们的核心资产） | 剧本契约、编译器、校验器、词库、队列/执行器、take 与指纹、审核流、UI、合成/字幕 | **完全独立**，纯 Python/TS，不含任何模型代码 |
| **执行层**（胶水） | `render_drama.py` 组 ComfyUI 工作流、轮询 `/prompt`、读 history | **半独立**：只依赖 ComfyUI 的 HTTP API，但节点名与权重名是写死的 |
| **模型层**（外部） | ComfyUI 0.45.3 + comfy-kitchen + MiniMax H3 权重 | **完全外部**：我们只是调用方 |

## 12. 别人已有 ComfyUI，能用这个项目吗？

**能，但要满足四个条件**（这就是「独立度」的具体边界）：

```
① ComfyUI 版本 ≥ 0.45.3（MiniMaxH3AddGuide、MiniMaxH3ImageConditioning 才存在）
② 装 comfy-kitchen 0.2.41（H3CastMember / H3CastToVideo —— cast 分支的全部实现）
③ 放齐权重：fl2va / ref2va / image 三个 UNET + qwen3vl 编码器 + 三个 VAE（约 90 GB）
④ 改配置：引擎地址（默认 127.0.0.1:8288）、数据目录、模型文件名
```

现在第 ④ 项只做到一半：**端口和路径有环境变量，但模型文件名、节点名、部分路径仍是硬编码**
（`minimax_h3_*` 出现在 8 个文件、`H3CastToVideo` 4 个文件、`8288` 20 个文件）。

**要做成「别人能装」的产品，需要一个适配层**（见 §15 路线）。

## 13. 开源可行性评估

### 可以开源的（无法律风险）

```
studio/core、studio/api、studio/exec、web-src、scripts/render_drama.py + merge/finalize
docs/（规则、格式、词库、评审经验）、skills/（drama-write / drama-review）
```

这些是我们的原创资产，价值也在这里。

### 不能直接开源的

| 对象 | 原因 |
|---|---|
| **模型权重**（90 GB） | MiniMax H3 权重的许可证需要逐份确认（社区/研究许可 vs 商用），且体积巨大 |
| **ComfyUI + comfy-kitchen** | 各自的许可证；我们只能声明「依赖」，不能打包 |
| **项目数据**（剧本/参考图/成片） | 我们自己的 IP |
| **API key**（如果有） | 环境变量隔离，不入库 |

### 结论

**可以开源，但只能开源「业务层 + 契约 + 文档 + 技能」，模型与 ComfyUI 走「自行安装」路径。**
这恰好也是绝大多数 AI 应用项目的开源形态（代码开源、权重自带）。

## 14. 优势（相对同类项目）

| 优势 | 具体是什么 | 别人难复制的点 |
|---|---|---|
| **剧本契约** | 60 条规则 + 54 个校验码 + 7 类中文词库 | 都是从真实返工里长出来的（REVIEW-LESSONS 12 条），不是拍脑袋 |
| **编译器** | 中文槽位 → H3 原生语法，枚举化、可测 | 需要长期实测 H3 的脾气（cfg=1、帧数 17k+5、状态不跨镜） |
| **指纹 + take** | 改稿只重渲受影响镜；混版合成有据可查 | 数据模型层面的设计，不是脚本堆出来的 |
| **审稿闭环** | A 写 / B 审 + 本地校验器双层 | 把「导演经验」变成了可执行的 checklist 和 JSON 契约 |
| **成本意识** | 5/8/10 秒档位 + 实测耗时表 + 单镜超时策略 | 长镜头的成本曲线（15 秒 = 8 倍成本）实测得出 |
| **可替换性** | 模型层只通过 HTTP 调用 ComfyUI | 换成别的视频模型，只需重写 render_drama 的组图部分 |

## 15. 要变成「可发布的开源项目」，还差四步

```

  · render_drama.py 拆成「通用工作流描述」+「ComfyUI 适配器」

第 4 步（持续）：示例数据
  · 用一篇虚构短剧做 demo（不含我们的 IP），保证 clone 下来能跑通一镜
```

## 17. 已知薄弱点（诚实清单）

```
· 硬编码：模型名/节点名/端口 分散在 20+ 文件，尚未完全配置化
· 单机单卡：队列是进程内线程 + SQLite，没有分布式能力
· 审稿依赖 LLM：本地校验器抓不到「写了但没渲出来」，只能靠渲后人工/审稿
· 竖屏未支持：目前只有 1344×768 横屏
· 资产工坊未完成：文生图链路已通（首次跑通封面），但还没接进 UI
· 字幕/音频：BGM 生成未落地（音频床接口已就绪）
```
